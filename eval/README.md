# 상세 이미지 글자 추출 평가

실제 Chromium에 확장을 올려 사례(상품 페이지)마다 상세 이미지 읽기를 실행하고, 사람이 만든 정답과 비교합니다. Gemini와 NVIDIA NIM을 같은 사례로 비교할 때 씁니다.

## 준비 (처음 한 번)

```bash
cd eval
npm install
npx playwright install chromium
```

## 실행

API 키는 환경 변수로 넘깁니다. 파일에 적지 마세요.

```bash
# 키가 있는 공급자를 모두 실행
GEMINI_API_KEY=... NVIDIA_API_KEY=... npm run eval

# 공급자·사례 골라서 실행
GEMINI_API_KEY=... node run.mjs --providers gemini --only fixture-basic

# 같은 사례를 5번씩 돌려 결과가 얼마나 흔들리는지 확인 (발표·문서에 옮길 결과는 이렇게)
GEMINI_API_KEY=... node run.mjs --providers gemini --repeat 5

# 브라우저 창을 띄워서 실행 (봇 차단이 의심될 때 확인용)
GEMINI_API_KEY=... node run.mjs --headed

# 키 없이 평가 도구 자체만 점검 (가짜 AI 서버 사용, 점수는 의미 없음)
node run.mjs --mock
```

| 환경 변수 | 기본값 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | 없음 | Gemini API 키 |
| `GEMINI_MODEL` | `gemini-3.8-flash` | Gemini 모델 |
| `NVIDIA_API_KEY` | 없음 | NVIDIA API 키 (무료 키는 개발·테스트 용도로만) |
| `NVIDIA_MODEL` | 없음 (NIM을 쓰면 필수) | NIM 모델 (이미지 입력 지원 모델). 추천 후보는 아래 "NVIDIA NIM 모델 고르기" 참고 |
| `NIM_BASE_URL` | `https://integrate.api.nvidia.com/v1` | NIM API 주소 |

결과는 화면에 표로 나오고, 자세한 내용(추출된 섹션 전체 포함)은 `eval/results/<시각>.json`에 저장됩니다. `results/`는 커밋하지 않습니다. 팀과 공유할 결과는 표를 문서로 옮겨 기록하세요.

AI 결과는 같은 사례라도 실행마다 달라질 수 있습니다. 한 번 돌린 점수를 그대로 옮기지 말고 `--repeat`로 여러 번 돌린 평균·최저·실패 횟수를 함께 적으세요. `--repeat`를 주면 회차를 바깥에 두고 사례를 돌아가며 실행하고(한 사례를 몰아서 돌리지 않음), 사례별로 묶은 표가 하나 더 나옵니다.

결과 파일의 `meta`에는 어떤 조건에서 돌렸는지가 남습니다. 결과를 문서로 옮길 때 코드 버전과 모델도 함께 적으세요.

| `meta` 항목 | 뜻 |
|---|---|
| `commit`, `dirty` | 실행한 코드의 커밋. `dirty: true`면 커밋하지 않은 변경이 있던 상태라 그 커밋만으로는 같은 결과를 다시 만들 수 없음 |
| `models` | 공급자별 모델 이름 (API 키는 남기지 않음) |
| `repeat`, `cases` | 반복 횟수, 사용한 사례 파일 |
| `startedAt`, `finishedAt`, `chromium`, `node`, `headed` | 실행 시각과 환경 |

## 지표

| 지표 | 뜻 |
|---|---|
| 글자 인식률 | 정답 문구 중 결과 어딘가에 나온 비율. 글자를 제대로 읽었는가 |
| 분류 정확도 | 정답 문구 중 맞는 섹션(가격·할인, 주의사항 등)에 들어간 비율 |
| 소요 시간 | 실행부터 결과 삽입까지. 매 사례마다 캐시를 비우고 잰다. 중앙값과 느린 쪽(p95)을 함께 본다. p95는 가장 가까운 순위로 고르므로 실행이 20번보다 적으면 사실상 가장 느린 값이다 |
| 인식률 최저 | 반복 실행 중 가장 낮았던 글자 인식률. 평균이 높아도 가끔 크게 놓치는지 본다 |
| 오류 | 페이지 접속 실패(봇 차단 포함), 상세 이미지 없음, API 오류 등 |

비교할 때 띄어쓰기·쉼표·대소문자 차이는 무시합니다. `39,000 원`과 `39000원`은 같은 것으로 봅니다.

## 사례 추가 (`cases.json`)

```json
{
  "id": "shop-a-tshirt",
  "url": "https://쇼핑몰/상품/123",
  "note": "상세 정보 탭이 기본으로 열려 있음",
  "expect": {
    "가격·할인": ["39,000원"],
    "소재·성분": ["면 100%"],
    "주의사항": ["세탁기 사용 불가"]
  }
}
```

- `expect`의 키는 확장이 쓰는 섹션 제목 중 하나입니다: 상품 요약, 가격·할인, 옵션·구성, 소재·성분, 영양정보, 사이즈·규격, 사용법, 배송·교환·반품, 주의사항, 기타
- 값은 **상세 이미지에 실제로 적힌** 핵심 문구입니다. 사람이 이미지를 보고 직접 적습니다. 긴 문장 전체보다 숫자·단어처럼 짧고 확실한 부분을 고르세요.
- 상품 페이지는 사라지거나 바뀔 수 있습니다. 정답을 만든 날짜를 `note`에 적어 두세요.
- `fixture-basic`은 평가 도구가 직접 그린 이미지라 정답이 확실합니다. 실제 쇼핑몰 결과와 비교하는 기준선으로 씁니다.
- `fixture-hard`는 AI가 자주 놓치는 모양(취소선 정가, 작은·흐린 각주, 표, 색 배경 위 밝은 글씨)을 모은 그림입니다. `lines`의 줄은 글자만 쓰거나 `{ "text", "size", "color", "bg", "strike" }` 객체로 모양을 정합니다.
- `real-ottogi-budae`는 실제 쇼핑몰 페이지입니다. 원재료·영양정보·알레르기가 작은 글씨로 빽빽한 식품 표시면이 있고, 같은 페이지에 다른 상품 썸네일과 닫힌 리뷰 탭 사진이 있어 상세 이미지만 고르는지도 확인합니다. 페이지가 바뀌면 정답을 다시 확인하세요.
- `url` 대신 `page`를 쓰면 평가 도구가 띄운 로컬 서버의 주소로 엽니다. (예: `"page": "/shop/index.html"`)

## 쇼핑몰형 테스트 페이지 (`shop/`)

저작권 걱정 없이 실제 쇼핑몰과 비슷한 페이지에서 확장을 시험하려고 만든 가상 쇼핑몰(솔빛리빙)의 상품 페이지입니다. 평가 사례 `shop-tumbler`가 이 페이지를 씁니다.

```bash
npm run shop    # http://127.0.0.1:8080/shop/ 에서 열기 (PORT 환경 변수로 포트 변경)
```

다른 PC에서 띄우거나 같은 네트워크의 다른 PC에서 접속하는 방법은 [테스트 페이지 구동 가이드](../docs/TEST-PAGE.md)를 참고하세요.

브라우저에 확장을 올리고 위 주소를 열면, 평소 쓰는 스크린리더로 확장 사용 전후를 직접 비교할 수 있습니다. 사용자 테스트 과제로도 씁니다. (예: "이 상품의 할인가와 세탁 주의사항을 찾아보세요")

페이지 구성:

| 스크린리더 기능 | 페이지에서 |
|---|---|
| 건너뛰기 링크 | 첫 Tab에서 "본문 바로가기" |
| 랜드마크 이동 | 배너(헤더), 검색, 주 메뉴, 현재 위치, 본문, 고객 안내(푸터) |
| 제목 이동 | h1 상품명, h2 가격·옵션 선택·상세정보·리뷰 등, h3 리뷰 제목 |
| 표 탐색 | 상품정보제공고시, 배송·교환·반품 표 (`caption`, 행 제목 `th scope="row"`) |
| 폼 | 색상 라디오 묶음(`fieldset`/`legend`), 수량 입력과 늘리기·줄이기 버튼, 찜하기 토글(`aria-pressed`) |
| 탭 | 상세정보·리뷰·상품문의·배송 탭. 방향키·Home·End로 이동 (WAI-ARIA 탭 패턴) |
| 실시간 알림 | 장바구니 담기, 옵션 미선택 안내를 `role="status"`로 읽어 줌 |
| 목록 | 메뉴, 현재 위치, 리뷰 목록 |
| 대체 텍스트 | 상품 사진은 대체 텍스트 있음. **상세 이미지는 실제 쇼핑몰처럼 대체 텍스트 없음** |

확장이 채워야 할 빈칸은 상세 이미지뿐입니다. 상세 이미지는 확장의 판별 기준을 모두 거치도록 구성했습니다.

- 세로로 긴 이미지 1장(`detail-01`) + 같은 너비(860px)로 잘라 붙인 이미지 3장(`detail-02~04`)
- 스크롤해야 불러오는 지연 로딩(`data-src`)
- 헤더 안의 넓은 배너 이미지(상세 이미지로 고르면 안 됨)

### 이미지

| 파일 | 만든 방법 |
|---|---|
| `images/product-*.jpg`, `lifestyle.jpg`, `lid-detail.jpg`, `cold-hot.jpg`, `store-banner.jpg` | Codex(ChatGPT 이미지 생성)로 만든 글자 없는 상품 사진 |
| `images/detail-0N.jpg` | `detail/detail.html`에 글자를 쓰고 위 사진과 합쳐 렌더링 |

상세 이미지 속 글자는 AI 이미지 생성에 맡기지 않았습니다. 생성 모델은 한글을 틀리게 그리는 경우가 많아 정답을 확신할 수 없기 때문입니다. 글자를 고치려면 `detail/detail.html`을 고친 뒤 다시 렌더링하고, `cases.json`의 `shop-tumbler` 정답도 함께 고칩니다. 정답 문구가 원본에 실제로 있는지는 `npm test`가 확인합니다.

```bash
npm run shop:build   # detail/detail.html → images/detail-0N.jpg
```

렌더링 결과 크기가 바뀌면 `index.html`의 상세 이미지 `width`·`height`도 맞춰 주세요(지연 로딩 자리 확보용).

## 한계

- 실행 전에 페이지를 끝까지 스크롤해 지연 로딩 이미지를 불러옵니다. 상세 정보가 탭 안에 숨겨져 클릭해야 나오는 사이트는 아직 처리하지 않습니다.
- 자동화 브라우저라서 일부 쇼핑몰은 접속을 막을 수 있습니다. 이 경우 오류로 기록됩니다. 실제 사용자 브라우저에서는 막히지 않을 수 있으니 `--headed`로 함께 확인하세요.
- 정답에 없는 내용을 지어낸 경우(환각)는 자동으로 잡지 못합니다. 결과 JSON의 `sections`를 사람이 확인해야 합니다.

## 요약·질문 응답 E2E 점검

API 키 없이 가짜 AI 서버와 평가용 쇼핑몰로 페이지 요약(`Alt+Shift+S`), 페이지에 질문하기(`Alt+Shift+Q`)가 실제 Chromium에서 제대로 동작하는지 확인합니다. AI 답의 품질이 아니라 확장의 동작(본문 수집, 요약 대화상자와 Esc 닫기·다시 열기, 원문 이동, 질문 대화상자, 포커스 이동, 캐시, 상세 이미지 결과 상자의 표시·접기·닫기·다시 열기)을 봅니다.

```bash
npm run e2e
```

항목마다 `PASS`/`FAIL`이 나오고, 하나라도 실패하면 종료 코드가 1입니다. 스크린샷(`summary.png`, `qa.png`, `detail.png`)과 AI에 보낸 요약 요청 글(`summary-prompt.txt`)은 `eval/results/e2e/`에 저장됩니다. 확장의 요약·질문 응답 코드를 고쳤다면 PR 전에 실행하세요.

## 온글 스크린리더 E2E 점검

API 키 없이 실제 Chromium에 확장을 올리고, 평가용 쇼핑몰·가짜 AI 서버·가짜 음성으로 온글 전체 동작을 확인합니다. 켜기 안내, 읽기·이동, 온글 메뉴, 사용 가이드, AI 자동 보완과 결과 모음, 파괴적 버튼 교차 검증, 요약·질문·상세 이미지 결과 바로 읽기, 점자 전달 테스트, 설정 화면, 상세 이미지 자리 안내, 요약을 닫으면 읽던 위치로 돌아오기(34개 항목).

```bash
npm run e2e:reader
```

음성은 서비스 워커의 `chrome.tts`를 가짜로 바꿔(소리 없이 바로 끝남) 화면 자막으로 확인합니다. 헤드리스 Chromium의 `chrome.tts`는 서비스 워커가 뜬 뒤 늦게 생기므로 생긴 뒤에 바꿉니다. 스크린샷은 `eval/results/e2e-reader/`에 저장됩니다. `--headed`를 붙이면 창을 띄웁니다.

실제 음성(이 컴퓨터의 한국어 음성)으로 들으면서 확인하려면 다음처럼 실행합니다. 소리가 나고, 문장을 끝까지 읽느라 기다리는 시간이 4배로 늘어납니다. 가짜 음성은 바로 끝나서 드러나지 않는 문제(안내가 쌓여 결과가 늦게 읽힘 등)를 찾을 때 씁니다.

```bash
npm run e2e:reader -- --headed --real-voice
```

## 읽기 정확성 (`reader/`)

```bash
npm run reader:accuracy
```

평가용 쇼핑몰을 온글 읽기 엔진으로 읽기 목록으로 만들고, 사람이 HTML을 보고 만든 정답표(`reader/shop-expected.json`)와 항목마다 비교합니다. 순서·종류·이름·상태가 모두 맞아야 맞은 것으로 셉니다. 처음 화면 전체, 옵션을 고른 뒤(선택·눌림·값 변화), 숨겨져 있던 리뷰·상품문의·배송 탭, 상세 이미지 결과 상자가 있을 때와 닫았을 때까지 7개 상황을 봅니다. 대체 텍스트가 빈 상세 이미지 자리의 안내("상세 이미지 4개, … Alt와 Shift와 D 키를 누르면 AI가 읽습니다")도 정답표에 들어 있습니다. 틀리면 "틀림/빠짐/더 읽음"으로 무엇이 다른지 보여 줍니다. 이름 없는 요소(★)는 AI 보완 전 상태인 "이름 없음"이 정답입니다. 쇼핑몰 HTML을 바꾸면 정답표도 함께 고칩니다.

## 점자 변환 정확도 (`braille/`)

```bash
npm run braille
```

1. **한국 점자 규정 예문** (`braille/rule-examples.json`): 2024 한국 점자 규정 고시의 예문 141개를 온글 변환 결과와 비교합니다. 모두 일치해야 합니다.
2. **liblouis 참고 비교** (`braille/sentences.json`): 개발용으로 설치한 liblouis(`brew install liblouis`, 확장에는 들어가지 않음)의 ko-g1·ko-g2 결과와 비교합니다. 다른 문장은 원문·점자·점 번호를 함께 보여 줍니다. liblouis가 규정과 다른 경우가 있으므로 일치율은 참고용입니다. liblouis가 없으면 이 단계는 건너뜁니다.

## NVIDIA NIM 모델 고르기

이전 기본 모델 `nvidia/nemotron-nano-12b-v2-vl`은 2026-08-26에 서비스가 종료되어 410 오류가 납니다. NIM은 모델이 자주 바뀌어 이제 기본 모델을 두지 않고, 설정 화면에서 추천 후보를 고르거나 직접 입력합니다. 추천 후보는 `extension/lib/settings.js`의 `NIM_RECOMMENDED_MODELS` 한 곳에서 관리하며, 아래 스크립트의 기본 후보도 같은 목록입니다. 한국어 인식 품질을 비교한 뒤 그 목록의 순서를 정하세요.

