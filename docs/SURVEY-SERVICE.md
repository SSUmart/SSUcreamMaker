# 평가 설문 서비스 구동 가이드

온글 평가 설문을 받고 결과를 비교하는 작은 웹 서비스(`eval/survey/`)를 띄우고 쓰는 방법입니다.

- **응답자**는 받은 링크로 들어가 로그인 없이 답합니다. 팀원용 링크와 사용자용 링크가 따로 있어, 어느 링크로 들어왔는지로 팀원 평가와 사용자 평가를 나눕니다.
- **관리자**는 비밀번호로 들어가 설문을 만들고, 응답 현황을 보고, 설문을 끝냅니다.
- 설문을 끝내면 **결과 페이지**(`/survey/result-1`처럼 설문마다 붙는 순번 주소)에서 **분석표**를 봅니다. 문항마다 세 점수를 나란히 비교합니다. 결과 페이지는 관리자만 보거나, 설문마다 "결과 공개"를 켜서 로그인 없이 주소로 보게 할 수 있습니다.

| 점수 | 어디서 오나 |
|---|---|
| AI 평가 | 관리자가 Claude, ChatGPT 등에 같은 설문을 물어 받은 답을 붙여 넣은 것. 여러 AI를 넣으면 평균 |
| 팀원 평가 | 팀원용 링크로 들어온 응답 |
| 사용자 평가 | 사용자용 링크로 들어온 응답 |

외부 패키지나 DB 없이 Node.js(22 권장)만 있으면 됩니다. 응답은 서버의 `eval/survey/data/` 폴더에 설문마다 JSON 파일 하나로 남고, 저장소에는 올라가지 않습니다(`.gitignore`).

## 1. 띄우기

테스트 서버에서는 온글몰과 함께 **8080 포트 하나**로 띄우고, 설문은 `/survey/` 아래에서 엽니다. 서비스(systemd)로 상시 띄우는 방법은 [평가용 웹 서비스 운영 가이드](EVAL-WEB-SERVICE.md)를 보세요.

```bash
cd eval
SURVEY_ADMIN_PASSWORD='정한 비밀번호' npm run web
```

브라우저에서 `http://127.0.0.1:8080/survey/admin`을 열고 비밀번호를 넣습니다. 같은 서버가 `/mall/`, `/shop/`도 내려줍니다. 비밀번호가 없으면 설문만 꺼지고 쇼핑몰은 열립니다.

| 환경 변수 | 기본값 | 뜻 |
|---|---|---|
| `SURVEY_ADMIN_PASSWORD` | 없음 | 관리자 비밀번호. 없으면 설문(`/survey/`)이 꺼짐 |
| `PORT` | `8080` | 포트 |
| `HOST` | `127.0.0.1` | 다른 기기에서 접속하거나 프록시·터널이 다른 기기에 있으면 `0.0.0.0` (같은 서버의 nginx가 넘겨줄 때만 그대로) |
| `SURVEY_PATH` | `/survey` | 설문 주소 앞부분 |
| `SURVEY_DATA_DIR` | `eval/survey/data` | 응답을 저장할 폴더 |
| `START` | `/mall/` | 첫 주소(`/`)로 들어오면 갈 곳 |

## 2. 설문만 따로 띄우기 (로컬 확인용)

설문 서버만 띄울 수도 있습니다. 이때는 주소 앞부분 없이 `/admin`, `/s/<토큰>`이고 포트는 8090입니다(`PORT`, `HOST`, `DATA_DIR`로 바꿈).

```bash
cd eval
SURVEY_ADMIN_PASSWORD='정한 비밀번호' npm run survey   # http://127.0.0.1:8090/admin
```

두 방식은 같은 데이터 폴더(`eval/survey/data/`)를 쓰므로 응답과 토큰은 같고, 링크 주소만 다릅니다(`:8090/s/<토큰>` ↔ `:8080/survey/s/<토큰>`). 링크는 띄운 서버의 관리자 화면에서 복사하세요.

- 서버를 껐다 켜도 응답과 링크는 그대로입니다(파일에 남음). 로그인만 다시 하면 됩니다.
- 응답 백업은 `eval/survey/data/` 폴더를 복사하면 됩니다.

## 3. 쓰는 순서

1. **설문 만들기**: 관리자 화면 아래 "새 설문 만들기"에 제목, 안내 문구, 문항을 넣습니다. 문항은 한 줄에 하나씩 쓰고, `# 영역 이름` 줄(`#` 뒤에 띄어쓰기)을 넣으면 그 아래 문항이 그 영역으로 묶여 분석표에 영역별 점수가 나옵니다.
   - **수정**: 설문 화면의 "설문 관리 → 수정"에서 제목과 안내 문구는 언제나 고칠 수 있습니다. 문항은 응답과 AI 답을 하나도 받지 않았을 때만 고칠 수 있습니다(받은 점수가 다른 문항의 점수가 되지 않도록).
   - **복제**: 응답을 받은 뒤 문항을 바꾸고 싶으면 "복제"로 문항이 같은 새 설문을 만들어 고칩니다. 새 설문은 링크가 새로 생기고 응답이 없습니다.
   - **삭제**: "삭제"하면 목록과 링크에서 사라집니다. 파일은 지우지 않고 데이터 폴더의 `trash/`로 옮기므로, 실수로 지웠으면 서버에서 `eval/survey/data/trash/<설문ID>-<지운 시각>.json`을 `eval/survey/data/<설문ID>.json`으로 옮기고 서비스를 다시 켜면 되살아납니다(`sudo systemctl restart ongeul-eval-web`).
2. **링크 나누기**: 설문 화면의 "팀원용 링크"는 팀원에게, "사용자용 링크"는 사용자 테스트 참가자에게 보냅니다. 한 PC에서 여러 참가자가 차례로 답해도 됩니다(응답 뒤 "다른 사람이 새로 응답하기").
3. **AI 평가 넣기**: "AI에 보낼 질문 글"을 복사해 AI에 보내고(README나 문서를 첨부하면 더 정확), 받은 답을 "AI 답"에 붙여 넣어 저장합니다. 답은 `번호 | 점수 | 이유` 줄이나 같은 모양의 마크다운 표면 됩니다. 점수 자리의 `NA`, `0`, `해당 없음`은 해당 없음으로 읽습니다. 여러 AI에 물어 저장하면 평균이 AI 점수가 됩니다. 설문을 끝낸 뒤에도 넣을 수 있습니다.
4. **설문 끝내기**: 응답을 다 받았으면 "설문 끝내기"를 누릅니다. 이후 링크로는 응답할 수 없고, 다시 열 수 없습니다.
5. **분석표 보기**: 끝낸 설문 화면의 "분석표 열기"를 누르거나, 설문 목록의 "결과 N번" 링크를 누르면 결과 페이지(`/survey/result-<순번>`)가 열립니다.
   - **순번**: 설문을 만든 순서대로 1, 2, 3…이 붙습니다(이 기능 전에 만든 설문에도 만든 순서대로 붙음). 지운 설문의 번호는 다시 쓰지 않아, 예전에 나눈 결과 주소가 다른 설문의 결과를 열지 않습니다. 결과 페이지 주소는 설문을 끝내기 전에도 설문 화면에서 미리 볼 수 있습니다.
   - **결과 미리보기**: 설문을 끝내기 전에는 설문 화면의 "결과 미리보기"로 지금까지 받은 응답의 분석표가 어떻게 보이는지 확인할 수 있습니다. 맨 위에 "미리보기: 아직 진행 중인 설문입니다"가 표시되고, 응답이 더 들어오면 숫자가 바뀝니다. 관리자만 볼 수 있으며, 결과 공개를 켜 두었어도 다른 사람에게는 설문을 끝낸 뒤에만 보입니다.
   - **결과 공개**: 기본은 관리자(로그인한 사람)만 봅니다. 설문 화면의 "결과 공개 (로그인 없이 주소로 보기)"를 켜면 주소를 아는 누구나 분석표를 볼 수 있어, 팀원이나 교수님께 주소만 보내면 됩니다. 응답자가 남긴 "하고 싶은 말"도 함께 보이므로 개인 정보가 없는지 먼저 확인하세요. 끄면 바로 다시 관리자만 봅니다. 공개하지 않은 결과나 없는 번호는 똑같이 "결과를 볼 수 없습니다"로 답해, 어떤 번호가 있는지 알 수 없습니다.
   - 공개해도 설문 ID, 응답 링크, 관리 기능은 결과 페이지에 나오지 않습니다.
   - 결과 페이지의 "인쇄 또는 PDF로 저장"으로 보고서를 만들고, 설문 화면의 "응답 내려받기 (CSV)"로 원자료를 엑셀에서 열 수 있습니다. `=`, `+`, `-`, `@`로 시작하는 의견은 엑셀이 수식으로 실행하지 않게 앞에 `'`를 붙여 내보냅니다.

## 4. 분석표 읽는 법

- 점수는 1(매우 불만족)~5(매우 만족)의 평균이고, 괄호 안은 응답 수입니다. 응답자(팀원·사용자)에게는 "해당 없음" 선택지가 없어 모든 문항에 1~5점으로 답합니다. AI 답의 "해당 없음"(과 해당 없음이 있던 때의 예전 응답)은 평균에서 뺍니다.
- 영역·전체 점수는 문항 평균의 평균입니다. 문항마다 응답 수가 달라도 같은 무게로 셉니다.
- **사용자 만족 비율**: 사용자 응답 중 4점 이상인 비율입니다. 응답자가 적을 때는 평균보다 읽기 쉽습니다.
- **사용자 − AI**, **사용자 − 팀원**: 실제 사용자가 AI나 팀원의 예상보다 높게(+) 또는 낮게(−) 평가한 정도입니다. ±0.5 이상이면 색으로 표시하고, 차이가 큰 문항은 "눈여겨볼 문항"에 모읍니다. 팀원이 생각한 것보다 사용자가 낮게 준 문항이 개선 우선순위입니다.
- 문항마다 "AI 이유"와 "사용자 점수 분포"를 펼쳐 볼 수 있고, 응답자의 "하고 싶은 말"은 맨 아래에 모입니다.

## 5. 접근성

응답자 중에는 스크린리더나 점자 디스플레이로 답하는 사람이 있어 응답 화면을 이렇게 만들었습니다.

- 문항마다 하나의 묶음(`fieldset`)이고, 점수 버튼은 "1점 매우 불만족"처럼 점수와 뜻을 함께 읽습니다.
- 빠진 문항이 있으면 오류 목록으로 초점이 가고, 목록의 문항을 누르면 그 문항으로 갑니다. 빠진 문항의 점수 버튼에는 "답하지 않은 문항입니다"가 함께 읽힙니다.
- 화면이 바뀌면(응답 완료 등) 제목으로 초점이 옮겨 처음부터 읽힙니다.
- 화면 크기가 작으면 점수 버튼이 한 줄에 하나씩 놓입니다.

## 6. 보안 메모

- 관리자 로그인은 12시간 유지되는 쿠키(`HttpOnly`, `SameSite=Strict`)이고, 관리 요청에는 전용 머리글을 요구해 다른 사이트에서 대신 보낼 수 없게 했습니다.
- 비밀번호를 1분 안에 10번 넘게 틀리면(동시에 넣어도 함께 셈) 1분 동안 로그인을 막습니다. 이 제한은 서버 전체에 걸리므로, 누가 일부러 계속 틀리면 관리자도 잠시 들어갈 수 없습니다. 추측하기 어려운 긴 비밀번호를 쓰세요.
- 응답 링크는 로그인 없이 여러 번 보낼 수 있습니다(한 PC에서 여러 참가자가 차례로 답하게 하려는 설계). 링크는 대상자에게만 보내고, 이상한 응답이 섞였으면 CSV로 확인하세요.
- 데이터 폴더의 설문 파일 하나가 깨져도 나머지 설문은 계속 동작하고, 깨진 파일은 서버 로그에 이름이 남습니다.
- HTTPS가 아니므로 학교·팀 내부망에서만 쓰세요. 인터넷에 공개하려면 nginx 같은 앞단에서 HTTPS를 붙입니다.
- 응답자의 이름 등 개인 정보는 받지 않습니다. "하고 싶은 말"에 개인 정보를 쓰지 않도록 안내하세요.

## 7. 점검

```bash
npm test                       # 저장소 루트: 계산·서버 테스트 포함
cd eval && npm run e2e:survey  # 실제 Chromium으로 한 포트 서버의 /survey/ 아래에서 만들기 → 응답 → AI 답 → 끝내기 → 결과 페이지(분석표, 공개 켜고 끄기) (임시 폴더 사용)
```
