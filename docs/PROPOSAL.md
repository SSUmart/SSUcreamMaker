# SSUcreamMaker 프로젝트 구성안

## 1. 개요

**주제**: AI를 결합한 새로운 웹 스크린리더. 화면을 읽어 글로 보여 주고(화면 오버레이), 소리로 읽고(브라우저 음성), 점자 디스플레이로 보내며, 기존 스크린리더가 못 읽는 부분은 AI가 채우고 긴 페이지는 요약하고 질문에 답한다.

**형태**: Chromium 기반 브라우저(Chrome, Edge, Whale) 확장 프로그램, Manifest V3

**확장 이름**: 온글 ("온전한 글". 사용자에게 보이는 이름이며, 프로젝트·저장소 이름은 SSUcreamMaker)

**방향 전환 (2026-10-15)**: 처음에는 "읽기는 사용자가 쓰던 스크린리더(센스리더, NVDA)가 하고 확장은 빈칸만 채운다"는 보조 도구로 설계했으나 이 방향은 접었다. 이제 **온글이 스크린리더 역할을 직접 하고**, 그 위에 AI 기능을 더한다. 기존 AI 기능(상세 이미지 읽기, 요약, 질문 응답, 항목 설명)은 스크린리더의 명령과 자동 보완으로 들어간다.

**원칙**
- 온글 하나로 웹페이지를 읽고, 이동하고, 조작할 수 있어야 한다
- 같은 내용을 세 곳으로 내보낸다: 화면 오버레이 글, 음성, 점자 디스플레이. 세 출력은 항상 같은 글에서 나온다
- AI는 기존 스크린리더가 못 하는 부분(읽을 수 없는 요소, 긴 페이지, 원하는 정보 찾기)에만 쓰고, AI가 만든 내용은 항상 AI라고 밝힌다

**현재 진행**: 8단계(테스트·평가) 진행 중. 스크린리더 기본 기능, 점자 출력, AI 기능은 구현했고 실제 AI 평가와 Windows 확인이 남았다. 진행 단계는 10장을 참고한다.

## 2. 대상 사용자

- **주 대상**: Windows PC의 크롬으로 쇼핑몰 등 웹을 이용하는 시각장애인
- **점자 사용자와 시청각장애인**: 스크린리더의 최종 목적지는 점자 디스플레이다. 듣지 못하는 사용자도 점자만으로 모든 기능을 쓸 수 있어야 한다
  - 출력은 짧고 구조화된 문장. 한 항목에 정보 하나. 이모지·장식 문구·마크다운 기호 금지
  - 결과와 오류는 사라지는 안내가 아니라 다시 읽을 수 있는 위치에 남긴다
  - 입력은 키보드(점자 키보드 포함)만으로 가능해야 한다
- **조작 방식**: 국내 사용자에게 익숙한 NVDA·센스리더 방식(읽기 모드의 한 글자 이동 키 등)
- **사용 전제**: 온글을 쓰는 동안 운영체제 스크린리더(NVDA, 센스리더)는 끈다. 둘이 동시에 읽거나 키가 충돌하지 않게 하기 위함
- **환경**: 개발은 macOS, 테스트와 최종 시연은 Windows 크롬

## 4. 기능 상세

### R1. 읽기 엔진

1. 페이지의 요소를 문서 순서대로 훑어 **읽기 순서 목록**을 만든다
   - 종류: 제목(수준), 링크, 버튼, 입력창(종류별), 체크박스, 라디오, 콤보 상자, 탭, 표, 목록, 그림, 영역(머리말·메뉴·본문·꼬리말), 문단
   - 이름: 접근 가능한 이름 계산(`aria-labelledby`, `aria-label`, `alt`, `label`, `title`, 글자 순)
   - 상태: 선택됨, 눌림, 펼쳐짐, 사용할 수 없음, 필수, 현재 페이지 등
   - 숨겨진 요소(`display:none`, `hidden`, `aria-hidden`)는 뺀다
2. 페이지가 바뀌면(동적 내용, 탭 패널, 무한 스크롤) 목록을 다시 만든다. 여러 변화는 0.3초 묶되, 계속 바뀌는 페이지에서도 1초에 한 번은 갱신한다. 보이는 탭만 계산하고, 읽던 요소가 사라지면 앞뒤 항목을 기준으로 가장 가까운 위치에 머문다. 초점이 새 요소로 옮겨지면 즉시 다시 만든다 (바뀐 부분만 갱신하는 방식은 큰 페이지 성능이 문제될 때 검토)
   - 제목 안의 링크, 표 칸 안의 버튼·입력창도 따로 항목이 된다. 레이아웃용 표(제목 칸 없이 화면 배치에 쓴 표)는 일반 글처럼 읽는다
   - 300자가 넘는 글은 문장 단위로 나눠 여러 항목으로 읽는다
   - 모달 대화상자가 열려 있으면 그 안만 읽는다
   - 열린 Shadow DOM 안도 읽는다. iframe은 "프레임, 안의 내용은 온글이 아직 읽을 수 없습니다"로 존재만 알린다(안 읽기는 후속 과제)
3. 읽기 문구 규칙: "장바구니 담기, 버튼", "상세정보, 제목 2", "화이트, 라디오 버튼, 선택 안 됨, 1/3", "수량, 숫자 편집창, 1"처럼 이름 → 종류 → 상태 → 값 → 위치 순서 (NVDA와 같은 순서). 목록·표·영역에 들어서면 "목록, 항목 4개", "표, 5행 2열", "탐색 영역"을 읽는다. 이름이 없으면 "이름 없음, 버튼"이고, AI가 채운 이름에는 "AI 추정"을 붙인다
4. 같은 블록 안의 글은 한 항목으로 묶고, 표는 행 단위로 읽는다. 레이블 글은 연결된 입력창의 이름으로 읽고 따로 읽지 않는다. 비밀번호 편집창은 글자 대신 "입력된 글자 N개"로 읽는다

### R2. 탐색·조작 명령

NVDA·센스리더의 읽기 모드 방식을 따른다. **온글 키**는 NVDA와 같이 `Insert` 또는 `Caps Lock`이고, `Ctrl+Alt`(macOS는 `Control+Option`)도 쓸 수 있다. macOS의 Caps Lock은 누르고 있는지 알 수 없어 Windows에서만 온글 키로 쓴다. 한 글자 키는 키 위치(`event.code`)로 판단해 한글 입력 상태에서도 동작한다.

| 키 | 동작 |
|---|---|
| `↓` / `↑` | 다음 / 이전 항목 |
| `Ctrl+Home` / `Ctrl+End` | 페이지 처음 / 끝 |
| `H` / `Shift+H`, `1`~`6` | 다음 / 이전 제목, 수준별 제목 |
| `K`, `B`, `F`, `E`, `X`, `R`, `C` | 링크, 버튼, 입력 요소, 편집창, 체크박스, 라디오 버튼, 콤보 상자 (`Shift`를 함께 누르면 이전) |
| `T`, `L`, `G`, `D` | 표, 목록, 그래픽, 영역 (`Shift`를 함께 누르면 이전). 없으면 "다음 제목 없음"처럼 안내 |
| `Tab` / `Shift+Tab` | 다음 / 이전 초점 이동 요소 (브라우저 기본 동작을 따라 읽음) |
| `Enter`, `Space` | 누르기 (링크 이동, 버튼, 체크박스). 상태가 바뀌면 바뀐 상태를 읽음 |
| 편집창에서 `Enter`, 또는 `Tab`·클릭으로 편집창에 초점 | 글쓰기 모드 (키를 페이지에 그대로 넘김). `Esc`로 읽기 모드로 돌아옴 |
| 온글 키 + `Space` | 읽기 모드와 글쓰기 모드 전환 |
| `Ctrl` | 읽기 멈춤 |
| 온글 키 + `↓` 또는 `A` | 지금 위치부터 끝까지 계속 읽기 (`A`는 NVDA 노트북 배열과 같고, Ctrl+Alt+화살표가 화면 회전인 PC를 위한 대안) |
| 온글 키 + `Tab` 또는 `L` | 현재 항목 다시 읽기 (`L`은 Windows의 Ctrl+Alt+Tab이 작업 전환이라 페이지에 오지 않는 경우를 위한 대안) |
| 온글 키 + `S` / `Q` / `D` | 요약(A3) / 질문(A4) / 상세 이미지 읽기(A2) |
| 온글 키 + `E` / `I` | 현재 항목 AI 설명 / AI 결과 모음 |
| 온글 키 + `1` | 키 도움말 |
| 온글 키 + `M` | 온글 메뉴 |

- 페이지 자체 단축키와 겹치면 읽기 모드에서는 온글이 처리한 키만 페이지로 넘기지 않고, 글쓰기 모드에서는 페이지에 그대로 넘긴다
- `Tab`, 마우스 클릭, 페이지 스크립트로 초점이 옮겨지면 그 항목을 읽는다
- 실시간 안내 영역(`role="status"`, `role="alert"`, `aria-live`)의 새 글을 읽는다. `alert`·`assertive`는 읽던 것을 끊고 읽는다
- 온글을 켜면 페이지 제목과 제목·링크 개수를 읽는다. 탭을 바꾸면 그 페이지 제목과 현재 항목을 읽고, 온글을 넣을 수 없는 페이지(`chrome://` 등)면 서비스 워커가 "이 페이지는 온글이 읽을 수 없습니다"라고 읽는다
- 온글 키 명령의 기능 키(요약 `S`, 질문 `Q`, 상세 이미지 `D`, 메뉴 `M`)와 온글 키 종류는 온글 설정 화면에서 바꾼다

#### 단축키 설계: 크롬 단축키 4개 + 온글 키 명령 + 온글 메뉴

크롬 확장은 기본 단축키를 **4개까지만** 정할 수 있고, 그 밖의 단축키는 사용자가 `chrome://extensions/shortcuts`에서 직접 지정해야 한다. 그런데 이 화면은 크롬 설정 화면이라 온글이 읽을 수 없어, 온글만 쓰는 사용자에게는 실질적으로 4개가 전부다. 또 페이지 안에서 키를 받는 방식은 개수 제한이 없지만 초점이 웹페이지 밖(주소창, 탭 목록)에 있으면 키를 받을 수 없다. 그래서 세 층으로 나눈다.

| 층 | 무엇에 쓰나 | 개수 | 어디서 동작 |
|---|---|---|---|
| 크롬 단축키 4개 | 어디서든 동작해야 하는 것: `Alt+Shift+O` 온글 켜기/끄기, `Alt+Shift+M` 온글 메뉴, `Alt+Shift+X` 읽기 멈춤, `Alt+Shift+R` 현재 위치 다시 읽기 | 4개 | 주소창 등 웹페이지 밖에서도 눌림 |
| 온글 키 명령 | 읽기·이동·AI 기능 (위 표) | 제한 없음 | 웹페이지 안 |
| 온글 메뉴 | 모든 기능을 목록에서 골라 실행. 단축키를 외우지 않아도 됨 | 제한 없음 | 웹페이지 안 |

- 초점이 웹페이지 밖에 있을 때 메뉴·다시 읽기 단축키를 누르면, 확장은 초점을 웹페이지로 옮길 수 없으므로 서비스 워커가 F6 안내를 읽는다(아래 안내 문구 원칙의 예). 사용자가 F6을 눌러 초점이 웹페이지로 돌아오면 온글이 이어서 메뉴를 열거나 현재 위치를 읽는다
- 온글을 넣을 수 없는 페이지(`chrome://` 등)에서는 서비스 워커가 그 이유와 빠져나가는 방법을 읽는다
- 요약·질문·상세 이미지 읽기·항목 설명은 크롬 단축키 기본값에서 빼고(명령은 남아 있어 직접 지정 가능) 온글 키 명령과 온글 메뉴로 옮겼다
- 온글 키 종류(`Insert`, `Caps Lock`, `Ctrl+Alt`)와 기능 키는 온글 설정 화면에서 바꾼다. 설정 화면은 확장 자체 페이지라 온글로 읽을 수 있다
- 이어 누르기 명령(온글 키를 떼고 글자 누르기)은 넣지 않았고, 다른 사이트의 iframe(결제창 등) 안에서의 동작은 별도 과제로 둔다

#### 온글 메뉴

- `Alt+Shift+M`(어디서든) 또는 온글 키 + `M`으로 연다. 화면 가운데 목록이 뜨고 "온글 메뉴. 12개 중 1번, 사용 가이드"처럼 읽는다(항목 수는 페이지에 따라 다름)
- 위아래 화살표로 고르고 `Enter`로 실행, `Esc`로 닫고 읽던 위치로 돌아감. 기능 이름의 첫 글자(영문, 또는 한글 초성: 2벌식 자판 위치 기준)로 이동
- 항목: 사용 가이드, 페이지 요약, 페이지에 질문하기, 상세 이미지 읽기(큰 그림이 있을 때만), 현재 항목 AI로 설명 듣기, AI 결과 모음, 제목 목록, 링크 목록, 영역 목록(골라서 그 위치로 이동), 키 도움말, 온글 설정, 온글 끄기. 요약부터 AI 결과 모음까지는 웹페이지에서만 보인다. 다른 기능(점자 전달 테스트 등)은 메뉴에 항목을 더할 수 있다
- 각 항목의 단축키를 함께 읽어 자주 쓰는 기능의 단축키를 익히게 한다

### 안내 문구 원칙

화면을 볼 수 없는 사용자에게는 안내마다 네 가지를 알린다.

1. **지금 어디에 있는지** (사용자는 위치를 볼 수 없음)
2. **어떤 키를 누르는지** (키 이름을 정확하게)
3. **누르면 무슨 일이 일어나는지** (동작의 결과)
4. **그다음 무엇을 하면 되는지**

예: 초점이 주소창에 있을 때 메뉴 단축키를 누르면 "지금 키보드 초점이 주소창이나 크롬 메뉴처럼 웹페이지 밖에 있어서 온글 메뉴를 열 수 없습니다. F6 키를 누르면 초점이 주소창에서 웹페이지 본문으로 옮겨지고, 이어서 온글 메뉴가 열립니다." F6을 누르면 "웹페이지 본문으로 이동했습니다. 온글 메뉴를 엽니다. 온글 메뉴. 12개 중 1번, 사용 가이드…"

- 안내가 길면 점자(한 줄 40칸)로 읽기 힘들고 숙련 사용자는 느려지므로, **자세한 안내와 짧은 안내**를 둔다. 설정 "안내": 자동(같은 안내를 처음 3번은 자세히, 그 뒤로는 짧게, 기본값) / 항상 자세히 / 항상 짧게
- 오류와 막힌 상황(읽을 수 없는 페이지, 초점이 웹페이지 밖, 온글이 꺼져 있음, 목록이 비어 있음)은 설정과 관계없이 항상 자세히 읽는다
- 키 이름 뒤에는 "키를"을 붙여 어떤 키 이름이든 조사가 자연스럽게 읽히게 한다 ("Alt와 Shift와 M 키를 누르면")
- 안내 문구는 한곳(`content/reader/guidance.js`)에 모아 서비스 워커와 페이지가 같이 쓴다

### R3. 화면 오버레이

- **자막 패널**: 지금 읽는 글을 화면 아래에 큰 글자로 표시(설정에서 화면 위로 변경). 음성과 같은 글
- 온글 화면은 top layer(popover)에 올려 페이지의 모달 대화상자 위에도 보인다
- **현재 위치 테두리**: 읽고 있는 요소에 두꺼운 테두리, 이동하면 화면도 따라 스크롤
- 페이지 디자인과 섞이지 않게 Shadow DOM으로 분리하고, 페이지의 읽기 대상에서는 뺀다

### R4. 음성

- `chrome.tts`로 서비스 워커에서 읽는다 (확장 페이지와 서비스 워커 모두에서 동작 확인)
- 새 항목으로 이동하면 읽던 음성을 바로 끊고, 계속 읽기에서는 대기열에 넣는다
- 음성 선택: 사용자가 고른 음성 → 운영체제 기본 한국어 음성(Windows "Microsoft Heami", macOS "유나") → 그 밖의 한국어 음성
- 속도·음성 설정 제공

**1단계 확인 결과 (macOS, Chrome 136)**: 8개 항목 중 7개 통과, 1개 참고

| 항목 | 결과 |
|---|---|
| 한국어 음성 | 9개 (유나, Eddy 등) |
| 확장 페이지·서비스 워커에서 읽기 | 통과, 시작까지 2~11ms |
| 즉시 중단 | 통과, 중지 후 5ms |
| 새 문장이 이전 문장을 끊음, 대기열 | 통과 |
| 속도 조절 | 통과 (2배속에서 0.46배 시간) |
| 읽는 위치(word) 이벤트 | 한국어 문장에서 1개만 옴 (참고. 읽는 위치 강조에는 쓰지 않음) |

Windows 확인은 확장의 `check/tts.html` 페이지로 한다.

### R5. 점자 출력 (가상 점자 디스플레이)

1. 오버레이와 같은 글을 **한국 점자**로 바꾼다 (기본: 약자를 쓰는 2종, 설정에서 1종 선택)
2. 점자 칸 데이터로 바꾼다: 칸 하나가 1바이트, 1~8번 점이 각 비트
3. 디스플레이 칸 수(기본 40칸, 20·32·40·80칸 선택)에 맞게 잘라 보낸다. 앞·뒤 줄 넘기기
4. **가상 점자 디스플레이**가 실제 기기 대신 데이터를 받는다. 받은 데이터를 점자 모양(⠁⠃ 등)으로 화면에 그리고, 커서 이동 버튼과 줄 넘기기 버튼을 흉내 낸다. 커서 이동 버튼은 NVDA처럼 링크·버튼·입력 요소면 누르고, 그 밖의 항목은 다시 읽는다
5. 실제 기기로 바꿀 때는 보내는 부분(전송 계층)만 바꾸면 되도록 나눈다. 전송 계층은 `name`, `cells`, `connected`, `write(칸 데이터)`, `onInput(기기 신호)`를 가진다. 기기 종류별 설계는 [docs/BRAILLE-DEVICES.md](BRAILLE-DEVICES.md)
6. 한 줄은 칸 수 안에서 낱말 사이(빈칸)로 끊고, 남는 칸은 빈칸으로 채워 보낸다

**한국 점자 변환 범위** (`content/reader/hangul-braille.js`, 직접 구현)
- 초성(된소리표 포함)·중성·종성(겹받침 포함), 첫소리 ㅇ 생략, 받침 ㅆ 약자
- 2종 약자: 가 사, ㅏ를 줄인 나 다 마 바 자 카 타 파 하(뒤에 모음으로 시작하는 글자가 오면 풀어 씀, 팠은 풀어 씀), 억 언 얼 연 열 영 옥 온 옹 운 울 은 을 인, 것, 까 싸 껏, ㅅ ㅈ ㅊ 뒤 '엉'은 '영' 약자(셩 졍 쳥은 풀어 씀)
- 약어: 그래서 그러나 그러면 그러므로 그런데 그리고 그리하여 (낱말 첫머리)
- 모음 사이 구분표: 모음 뒤 '예', ㅑ ㅘ ㅜ ㅝ 뒤 '애'
- 숫자: 수표, 숫자 안 쉼표·소수점, 숫자 뒤 ㄴ ㄷ ㅁ ㅋ ㅌ ㅍ ㅎ·'운'은 한 칸 띄움
- 로마자: 로마자표·대문자표, 한글이 바로 이어지면 로마자 종료표
- 자주 쓰는 문장 부호. 바꾸지 못한 글자는 6점 모두 올린 칸으로 표시하고 관리자 도구에 보여 줌
- 정확도는 테스트 단계에서 한국 점자 규정 예문과 개발용 liblouis(ko-g1, ko-g2) 결과로 확인한다

### T1. 점자 전달 테스트 (관리자 도구)

- 설정 화면에서 "관리자 도구 켜기"를 켜면 화면 오른쪽 아래에 "점자 전달 테스트" 버튼이 생기고, 온글 메뉴에도 같은 항목이 생긴다
- 누르면 화면 오른쪽 위에 가상 점자 디스플레이와 전달 결과 패널을 보여 주고, 다시 누르면 숨긴다. 패널은 온글이 글을 읽을 때마다 갱신된다
- 관리자 도구를 끄면 버튼도 사라지고 온글은 일반 스크린리더로만 동작한다 (점자 출력은 항상 가상 기기로 전송됨)

| 항목 | 내용 |
|---|---|
| 기기 상태 | 연결 여부, 기기 이름(가상), 칸 수 |
| 보낸 원문 | 스크린리더가 읽은 글 |
| 변환 결과 | 점자 모양과 칸별 점 번호 |
| 보낸 데이터 | 칸별 숫자 값 |
| 전송 결과 | 성공·실패, 오류, 걸린 시간, 시각 |
| 왕복 확인 | 가상 기기의 커서 이동 버튼·줄 넘기기 버튼을 누르면 그 신호를 받았는지 표시 |
| 바꾸지 못한 글자 | 점자 규칙에 없는 글자가 있으면 표시 |

### A1. 자동 보완

1. R1이 이름 없는 요소(이름 없는 버튼·링크·탭·편집창, `alt` 없는 그림, `onclick`만 있는 `div`)를 만나면 표시해 둔다
2. 그 요소를 읽으면 "이름 없음, 버튼"을 읽은 뒤 "버튼 이름이 없어 읽을 수 없는 부분입니다. AI가 내용을 분석하고 있습니다. 이 자리에 있으면 끝나는 대로 읽어 드리고, 다른 곳으로 이동해도 분석은 계속됩니다. 결과는 온글 키와 I 키를 함께 누르면 AI 결과 모음에서 들을 수 있습니다"라고 안내한다(익숙해지면 "AI 분석 중")
3. 항목 정보(`content/reader/describe.js`: 종류, 글자, 상태, 쿼리 뺀 주소, 앞 제목, 주변 글, 클래스·아이디 단서, 그림)를 AI에 보내 2~15자 이름을 받는다(`label-item`, `lib/explain.js`의 `buildLabelPrompt`). 확신이 낮으면 "…일 수 있음"
4. 끝났을 때 아직 그 항목에 있으면 "분석 결과: 장바구니 담기, AI 추정, 버튼"을 이어 읽는다. 다른 곳에 있으면 알리지 않는다(분석이 끝날 때마다 말하면 정보가 너무 많으므로, 궁금하면 사용자가 AI 결과 모음을 연다). 그 뒤로는 그 항목을 "장바구니 담기, AI 추정, 버튼"으로 읽는다
5. 페이지를 열면 앞쪽 이름 없는 항목 5개를 미리 분석하고, 한 번에 하나씩, 페이지당 최대 30개까지 분석한다. 같은 항목 정보는 브라우저 세션 동안 캐시
6. 파괴적 동작 단서(delete, cancel, 삭제, 취소, 탈퇴, 결제 등)가 요소에 있는데 AI 이름에 그런 뜻이 없으면 "용도 불명확, ○○ 관련일 수 있음"으로 읽는다
7. AI가 꺼져 있거나 키가 없으면 페이지에서 한 번만 이유와 설정 방법을 알리고 더 묻지 않는다. 설정 "이름 없는 항목 AI 자동 분석"으로 끌 수 있다

**AI 결과 모음** (온글 키 + `I`, 온글 메뉴): 자동 보완, 요약, 상세 이미지 읽기, 질문 답, 현재 항목 설명 결과를 최근 것부터 모은다. 분석 중인 것은 "AI 분석 중"으로 보이고, 고르면 그 위치로 가서 읽는다(요약·상세 내용은 처음부터 이어 읽고, 위치가 없으면 결과 글을 읽음)

**현재 항목 AI 설명** (온글 키 + `E`, 온글 메뉴): 지금 읽는 항목을 AI가 1~3문장으로 설명하고 결과 모음에도 넣는다. 예전 클릭형 항목 설명 모드(`content/explain.js`)를 대신해 메뉴에서는 뺐다(크롬 단축키 화면에서 직접 지정하면 여전히 쓸 수 있음)

### A2. 상세 이미지 글자 읽기 (기존 F2)

1. 명령(온글 키 + `D`, 온글 메뉴, 툴바 아이콘)으로 실행한다. 완료되면 추출한 내용을 처음부터 바로 읽는다
2. 상세 설명 이미지 탐지: 실제로 내려받아 크기를 확인한 뒤, 세로로 긴 이미지(높이 ≥ 너비×1.2) 또는 같은 너비로 3장 이상 이어 붙인 이미지 묶음. 헤더·내비게이션·푸터 안 이미지는 제외
3. 이미지를 너비 1000px 이하, 높이 1000px 조각으로 나눔 (경계 80px 겹침, 최대 40조각)
4. AI로 글자를 읽고 항목별로 구조화 (상품 요약, 가격·할인, 옵션·구성, 소재·성분, 사이즈·규격, 사용법, 배송·교환·반품, 주의사항, 기타)
   - Gemini: 조각 전체를 한 번에 보내 JSON으로 정리
   - NVIDIA NIM: 조각별로 글자를 읽은 뒤 한 번 더 정리
5. 결과를 상세 이미지 앞에 제목 구조로 넣고, 읽기 목록에 반영해 그 위치부터 읽는다
6. 같은 이미지·같은 모델 결과는 브라우저 세션 동안 캐시

### A3. 내용 요약 (기존 F4)

1. 명령(온글 키 + `S`, 온글 메뉴)으로 실행. 완료되면 요약 상자를 처음부터 바로 읽는다
2. 본문 수집: `main`(없거나 짧으면 `body`)에서 머리말·꼬리말·메뉴·`aside`·`aria-hidden`·입력창 값을 빼고 문단 단위로 모음. 표는 행, 정의 목록은 이름과 값을 한 문단으로. 닫힌 탭 패널 포함. 문단 600자, 전체 3만 자 상한. 문단마다 번호를 붙여 보내고 AI는 근거 번호를 돌려줌
3. 결과를 요약 상자로 넣고 바로 읽는다(오버레이·음성·점자). 항목마다 "원문으로 이동"으로 근거 위치부터 이어 읽기
4. 같은 페이지 글·같은 모델이면 캐시

### A4. 질문 응답 (기존 F5)

1. 명령(온글 키 + `Q`, 온글 메뉴)으로 질문 대화상자를 열고 입력
2. 페이지 글(A2 결과 포함)만 근거로 답함. 근거가 없으면 "페이지에서 찾지 못했습니다". 숫자는 원문 그대로
3. 답을 바로 읽고, "근거 위치로 이동"으로 그 위치부터 이어 읽기
4. 이전 질문 3개까지 이어서 이해

## 7. 안전·개인정보 원칙

0. **AI는 기본 꺼짐**: 사용자가 설정에서 켜고 API 키를 넣어야 동작. 켜는 곳에 외부 AI로 전송되고 요금이 청구된다는 안내 표시. 스크린리더 기본 기능(R1~R5)은 AI 없이 동작
1. **AI 표시**: AI가 만든 이름·글에는 항상 "AI 추정", "AI 추출", "AI 생성", "AI 답변"을 붙임
2. **파괴적 동작 교차 검증**: AI 설명과 DOM 신호(`delete`/`remove`/`취소`/`탈퇴` 등)가 다르면 "용도 불명확"으로 읽음
3. **전송 범위**: 입력창·편집 영역의 값과 링크 주소의 쿼리는 보내지 않음. 자동 보완(A1)은 이름 없는 요소 하나의 정보와 그림만 보냄. Gemini 무료 등급은 보낸 내용이 Google의 서비스 개선에 쓰일 수 있음을 안내
4. **근거 원칙 (A3·A4)**: 페이지에 있는 내용으로만 요약·답변. 숫자는 원문 그대로. 근거 번호를 확장이 검증
5. **API 키 보관**: `chrome.storage.local`에만 저장 (동기화 안 함)
6. **사용량 보호**: A2·A3·A4는 명령으로만 실행. A1 자동 보완은 끌 수 있고 결과를 캐시
7. **대행 안 함**: 사용자가 누른 동작만 실행하고, 클릭·입력·결제를 대신 하지 않음
8. **권한**: 현재 `<all_urls>`, `scripting`, `storage`, `tts`

**S6에서 만든 것: AI 결과 모음** (온글 키 + `I`, 온글 메뉴, 자세한 내용은 4장 A1)

**S6 응답 속도 개선**: 긴 페이지(보낼 글 6,000자 초과)에서 질문하면 질문과 낱말이 겹치는 문단과 그 앞뒤, 페이지 앞부분만 보낸다(번호는 원래대로). NVIDIA NIM은 상세 이미지 조각을 3개씩 동시에 읽고(무료 키 분당 한도 안), 요약·답변은 답 길이 상한을 줄였다. 요청한 AI 결과는 끝나는 대로 바로 읽는다
- 자동 보완: 이름 없는 요소를 읽으면 AI 분석 중임을 알리고 탐색을 계속하게 한다. 끝났을 때 아직 그 요소에 있으면 바로 이어 읽고, 다른 곳에 있으면 알리지 않는다. 그 요소에도 이름을 붙여 다시 오면 "AI 추정"으로 읽는다
- 사용자가 요청한 AI(요약, 질문, 상세 이미지 읽기)는 끝나면 바로 읽고 결과 모음에도 저장한다
- 결과 모음 항목에서 Enter를 누르면 그 위치로 이동해 이어 읽는다. 자동 분석은 사용자가 지나간 요소와 화면 근처 몇 개만 하고 결과는 캐시한다
- 항목 설명 모드(시험 기능)는 이 기능으로 합친다

**S7 처음 사용 안내**: 설치 직후 서비스 워커가 온글 소개, 다른 스크린리더를 끄라는 안내, 켜는 단축키, 메뉴의 사용 가이드를 소리로 알리고 설정 화면을 연다. 설정 화면 맨 위 "시작하기" 단계와 사용 가이드 전문, 온글을 켤 때 안내에도 사용 가이드 위치를 넣었다

**S10 처음 사용 가이드**: 온글 메뉴의 첫 항목. 목차(9장)에서 장을 고르면 화면에 띄우고 문단 단위로 읽는다. 위아래 화살표로 문단 이동, 장 끝에서 다음 장으로, Esc로 목차. 키 이름은 사용자가 바꾼 설정을 따른다

**S8에서 만든 것 (키 없이 할 수 있는 것)**
- 평가용 쇼핑몰에 이름 없는 요소 5종(★, `docs/TEST-PAGE.md`)
- 점자 변환 정확도: 2024 한국 점자 규정 예문 141개 모두 일치. 개발용 liblouis 3.39와는 270문장 중 236개(87.4%) 일치, 다른 34개는 liblouis가 규정과 다른 경우(팠, 구분표, 숫자 속 쉼표·소수점, 따옴표·괄호, 로마자표·종료표). 한계: 영어는 영어 약자(UEB 2종)를 쓰지 않고 알파벳 그대로 적음, %처럼 한국 점자 규정에 없는 기호는 정하지 않음
- 읽기 정확성(`npm run reader:accuracy`): 사람이 만든 정답표와 비교해 5개 상황(처음 화면, 옵션 고른 뒤, 리뷰·상품문의·배송 탭) 140/140 일치. 측정하며 화면에 안 보이는 글(sr-only)이 문장에서 떨어져 따로 읽히던 문제를 찾아 고침(고치기 전 136/140)
- 읽기 E2E(`npm run e2e:reader`): 가짜 AI와 가짜 음성으로 켜기·이동·메뉴·사용 가이드·자동 보완·결과 모음·교차 검증·요약·질문·상세 이미지·점자 전달·설정 화면 32개 항목 확인. macOS 실제 음성으로도 모두 통과(`--headed --real-voice`)

**뒤로 미룬 것**: iframe 안 읽기(지금은 존재만 안내), `addEventListener`로만 클릭을 받는 요소·`role` 없는 `contenteditable` 탐지(S6 자동 보완과 함께), Windows 실기기에서 확인할 항목(`display: contents` 영역, 설정 화면에서 크롬 단축키, 한글 입력기 상태의 한 글자 키, `Alt+Shift`와 입력 언어 전환, `Ctrl+Alt+화살표` 화면 회전)

이전 계획의 단계 중 M3(F2), M6(F4), M7(F5)는 구현 완료. M1·M2(F1 라벨링)는 A1 자동 보완으로 대체. M8(점자 우선 보강)은 오버레이·음성·점자 출력(S4·S5)으로 흡수.

## 11. 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| 운영체제 스크린리더와 동시 실행 | 이중 읽기, 키 충돌 | 처음 사용 안내에서 끄도록 안내. 시연·테스트 전 확인 |
| 페이지 단축키와 온글 키 충돌 | 명령 실행 불가 또는 페이지 오동작 | 읽기 모드에서는 온글이 키를 먼저 받고, 글쓰기 모드에서는 페이지에 넘김 |
| Windows 한국어 음성 미설치 | 음성 출력 불가 | 음성 확인 페이지와 처음 사용 안내에서 설치 방법 안내 |
| 큰 페이지에서 읽기 엔진 속도 | 이동 지연 | 필요한 부분만 계산, 바뀐 부분만 갱신 |
| 동적 페이지(SPA) | 읽기 목록과 실제 화면 불일치 | 변화 감지 후 갱신, 현재 위치 유지 |
| 한국 점자 변환 정확도 | 점자 사용자가 잘못 읽음 | 규정 예문으로 테스트, 참고 구현(liblouis)과 비교 |
| AI 지연 | 탐색 흐름이 끊김 | 미리 처리, 캐시, "AI 확인 중"을 먼저 읽고 이어 읽기 |
| 자동 보완 환각 | 잘못된 조작 유도 | AI 표시, 파괴적 동작 교차 검증 |
| 무료 AI 한도 | 시연 중 실패 | 캐시, 한도 초과 안내, 리허설 |
| 브라우저 밖은 읽을 수 없음 | 주소 입력·탭 이동은 운영체제 도움 필요 | 탭 전환 시 탭 제목 읽기, 읽을 수 없는 페이지 안내. 한계를 문서에 명시 |
| 확장을 넣을 수 없는 페이지(`chrome://`, 웹스토어) | 온글 동작 불가 | 서비스 워커에서 음성으로 "읽을 수 없는 페이지" 안내 |
