# SSUcreamMaker 프로젝트 구성안

## 1. 개요

**한 줄 주제**: 스크린리더가 "버튼", "그래픽"이라고만 읽는 부분과 이미지 속 글자를, 사용자 브라우저의 확장 프로그램이 AI로 채워주는 도구

**형태**: Chromium 기반 브라우저(Chrome, Edge, Whale) 확장 프로그램, Manifest V3

**현재 진행**: F2(상세페이지 글자 추출)를 먼저 구현했습니다. AI는 사용자가 옵션에서 켜고 자기 API 키(Google Gemini 또는 NVIDIA NIM)를 넣어 씁니다. 사용법은 README를 참고하세요.

**원칙**: 확장은 스크린리더를 대신하지 않습니다. 페이지의 빈칸(라벨, 텍스트, 구조)을 채우기만 하고, 읽기는 사용자가 쓰던 스크린리더(센스리더, NVDA, JAWS)가 그대로 합니다.

### 왜 확장 프로그램인가

| 비교 항목 | URL 변환 웹서비스 | 브라우저 확장 (선택) |
|---|---|---|
| 페이지를 가져오는 주체 | 우리 서버 | 사용자 브라우저 |
| 봇 차단 | 막힐 수 있음 | 해당 없음 |
| 로그인 페이지 | 불가 | 가능 |
| 클릭·구매 등 조작 | 불가 (복사본) | 가능 (원본 위에서 동작) |
| 저작권·재배포 | 검토 필요 | 사용자 화면에서만 보강 |
| 기존 스크린리더 | 그대로 사용 | 그대로 사용 |

## 2. 대상 사용자

- **주 대상**: Windows PC에서 센스리더, NVDA로 쇼핑몰을 이용하는 시각장애인
- **설계 원칙**: 점자 디스플레이 사용자도 고려해 출력은 짧고 구조화된 문장으로 함. 이모지·장식 문구 금지.
- **확장 가능성**: 표준 WebExtension API로 작성해 이후 Firefox(Android), Safari(iOS)로 이식 검토

## 3. 범위

### 범위 내

| # | 기능 | 지금 스크린리더가 읽는 것 | 확장 적용 후 |

## 4. 기능 상세

### F1. 요소 라벨링

1. 접근 가능한 이름이 없는 요소 수집: `button`, `a`, `img`, `[role=button]`, `onclick`이 붙은 `div`/`span`
2. 단계식 추정 (싼 것부터)
   - **1단계 DOM 단서**: `title`, `alt`, 클래스명(`icon-cart`, `btn-delete`), SVG `<use href="#trash">`, 주변 텍스트, 부모 `form`의 `action`
   - **2단계 OCR**: 버튼 이미지 안의 글자
   - **3단계 VLM**: 1, 2단계로 안 될 때만 해당 영역 스크린샷 전송
3. 주입
   - `aria-label="장바구니 담기, AI 추정"`
   - 가짜 버튼(`div onclick`)에는 `role="button"`, `tabindex="0"`, Enter/Space 키를 클릭으로 연결
4. 유지: MutationObserver로 프레임워크가 다시 그려 라벨이 지워지면 재주입

### F2. 상세페이지 글자 추출

0. 사용자가 툴바 아이콘 또는 `Alt+Shift+D`로 실행 (자동 실행하지 않음: 사용자 API 요금 보호)
1. 상세 설명 이미지 탐지: 실제로 내려받아 크기를 확인한 뒤, 세로로 긴 이미지(높이 ≥ 너비×1.2) 또는 같은 너비로 3장 이상 이어 붙인 이미지 묶음을 고름. 헤더·내비게이션·푸터 안 이미지는 제외
2. 이미지를 너비 1000px 이하, 높이 1000px 조각으로 나눔 (경계 80px 겹침, 최대 40조각)
3. AI로 글자를 읽고 항목별로 구조화 (상품 요약, 가격·할인, 옵션·구성, 소재·성분, 사이즈·규격, 사용법, 배송·교환·반품, 주의사항, 기타)
   - Gemini: 조각 전체를 한 번에 보내 JSON으로 바로 정리
   - NVIDIA NIM: 조각별로 글자를 읽은 뒤 텍스트로 한 번 더 정리 (모델마다 다중 이미지 지원이 달라서)
4. 상세 이미지 바로 앞에 텍스트 영역 삽입
   - `<section aria-label="상세 이미지 내용, AI 추출">` 안에 `h3` 제목 구조로 작성
   - 화면에서는 숨기되 스크린리더는 읽도록 `sr-only` 방식 사용 (`display:none` 금지)
5. 완료되면 삽입한 제목으로 포커스 이동, 진행 상황과 오류는 `role="status"` 영역으로 안내
6. 같은 이미지·같은 모델 결과는 브라우저 세션 동안 캐시해 다시 실행해도 AI를 다시 부르지 않음

### F3. 페이지 구조 요약

1. 단축키(예: `Alt+Shift+S`, `chrome.commands`)로 요약 열기 (F2가 `Alt+Shift+D` 사용)
2. 페이지 맨 앞에 요약 영역 삽입: "상단 메뉴, 상품 정보, 상세 설명, 리뷰, 구매 버튼"
3. 항목을 선택하면 해당 영역으로 포커스 이동
4. 기존 랜드마크·제목이 충분하면 그것을 활용하고, 없을 때만 AI로 추정

## 5. 시스템 구조

중계 서버 없이 확장이 사용자가 입력한 API 키로 AI를 직접 호출합니다(BYOK, Bring Your Own Key).

```
┌──────────────── 사용자 브라우저 ────────────────┐
│                                                  │
│  쇼핑몰 페이지 (사용자 로그인 상태 그대로)          │
│     ▲ 상세 텍스트 영역 삽입, 상태 안내             │
│     │                                            │
│  Content Script (content/detail.js)              │
│   ├ 후보 이미지 수집 (지연 로딩 data-src 포함)       │
│   └ 결과 삽입, 포커스 이동, role=status 안내       │
│     │ chrome.runtime 메시지                        │
│     ▼                                            │
│  Service Worker (background.js)                  │
│   ├ 설정 확인 (AI 꺼짐·키 없음이면 안내만)           │
│   ├ 이미지 내려받기 + 크기로 상세 이미지 판별        │
│   ├ OffscreenCanvas로 조각 분할·JPEG 압축          │
│   ├ 캐시 (storage.session)                       │
│   └ AI 호출 ─────────────────────────┐           │
│                                      │           │
│  Options 페이지: AI 켜기/끄기, 공급자, API 키, 모델 │
│  (storage.local, 동기화 안 함)          │           │
└──────────────────────────────────────┼───────────┘
                                       ▼
              Google Gemini API  또는  NVIDIA NIM API
              (사용자 본인 키, 요금도 사용자 계정)
```

### 구성 요소별 역할

| 구성 요소 | 파일 | 역할 |
|---|---|---|
| Content Script | `extension/content/detail.js` | 후보 이미지 수집, 결과 삽입, 안내 |
| Service Worker | `extension/background.js` | 실행 흐름, 이미지 처리, 캐시 |
| 상세 이미지 판별 | `extension/lib/detect.js` | 크기 기준 선택 |
| 조각 분할 | `extension/lib/tiles.js` | 조각 계획, JPEG 인코딩 |
| AI 공급자 | `extension/lib/providers.js` | Gemini, NIM 호출 |
| 결과 정리 | `extension/lib/structure.js` | 프롬프트, 응답 JSON 정리 |
| 설정 | `extension/lib/settings.js`, `extension/options/` | 기본값, 저장, 설정 화면 |

### 중계 서버를 두지 않은 이유

- API 키를 확장에 넣지 않으려고 중계 서버를 계획했으나, 사용자가 자기 키를 넣는 방식이면 그 필요가 없음
- 운영 비용과 서버 쪽 개인정보 보관 문제가 사라짐
- 대가: 사용자가 API 키를 직접 발급해야 함. 발급 과정의 접근성은 사용자 테스트에서 확인 필요

## 6. 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 확장 | JavaScript(ES 모듈), Manifest V3, 빌드 도구 없음 | 의존성 없이 바로 로드 가능. 규모가 커지면 TypeScript·WXT 도입 검토 |
| 단위 테스트 | Node 내장 `node --test` | 의존성 없음. `npm test` |
| E2E 확인 | Playwright + Chromium, 가짜 AI 서버 | 이미지 처리·삽입·접근성 트리까지 실제 브라우저에서 확인 |
| AI | Google Gemini (기본 `gemini-3.8-flash`), NVIDIA NIM (기본 `nvidia/nemotron-nano-12b-v2-vl`) | 사용자가 옵션에서 모델 변경 가능. 한국어 정확도는 평가 단계에서 비교 |

## 7. 안전·개인정보 원칙

0. **AI는 기본 꺼짐**: 사용자가 옵션에서 켜고 API 키를 넣어야 동작. 켜는 곳에 이미지가 외부 AI로 전송되고 요금이 청구된다는 안내 표시
1. **AI 표시**: AI가 만든 라벨과 텍스트에는 항상 "AI 추정" 또는 "AI 추출"을 붙임
2. **파괴적 동작 교차 검증**: AI 결과와 DOM 신호(`delete`/`remove`/`취소`/`탈퇴` 키워드, POST 폼)가 다르면 "용도 불명확 버튼"으로 표시
3. **전송 범위**: F2는 상세 설명 이미지만 보내고 화면 스크린샷은 보내지 않음. 스크린샷을 보내는 F1·F3 단계에서 전송 차단 도메인(결제·금융·의료·로그인)과 입력 필드 마스킹 적용
4. **API 키 보관**: `chrome.storage.local`에만 저장 (기기 간 동기화 안 함). 암호화되지는 않으므로 공용 PC에서는 사용 후 키 삭제 안내
5. **사용량 보호**: 자동 실행 없이 사용자가 실행할 때만, 한 번에 최대 40조각
6. **대행 안 함**: 확장은 클릭·입력을 대신 하지 않음
7. **권한**: 상세 이미지가 어느 CDN에 있을지 알 수 없어 현재는 `<all_urls>`를 사용. 웹스토어 배포 전 `optional_host_permissions`로 바꿔 사용자가 허용한 사이트만 쓰도록 축소

## 9. 평가 계획

| 지표 | 측정 방법 | 목표 (초안) |
|---|---|---|
| 기준선 | 대상 쇼핑몰의 라벨 없는 요소 수, KWCAG 2.2 위반 항목 | 측정 |
| DOM 단서 해결률 | AI 없이 1단계만으로 맞힌 비율 | 측정 (AI 효과 비교용 기준) |
| 라벨 정확도 | 접근성이 잘 된 사이트에서 라벨을 지운 뒤 추정 결과와 원래 라벨 비교 | 70% 이상 |
| 파괴적 버튼 오인 | 삭제·취소류 버튼을 다른 동작으로 잘못 라벨링한 비율 | 0%에 근접 |
| 상세 추출 정확도 | 상품 10~20개에서 핵심 항목 추출 정확도 | 측정 후 설정 |
| 지연시간 | 라벨이 반영되기까지 시간 (p50/p95, 캐시 적중·미적중 구분) | 측정 후 설정 |
| 스크린리더 호환 | 센스리더, NVDA, JAWS에서 주입 라벨이 실제로 읽히는지 | 3종 모두 확인 |
| 실사용 | 시각장애인 사용자의 과제 수행 시간 비교 (확장 사용 전후) | 단축 여부 |

**대상 사이트**: 국내 쇼핑몰 5~10곳 (M0에서 확정)
**사용자 테스트**: 한국시각장애인연합회 또는 교내 장애학생지원센터를 통해 모집

## 10. 진행 단계

F2(상세페이지)를 먼저 진행하는 순서로 바꿨습니다. 중계 서버가 빠지면서 이전 M2(AI 연동)의 공통 부분이 F2 구현에 포함되었습니다.

| 단계 | 내용 | 상태 | 완료 기준 |
|---|---|---|---|
| M3 상세페이지 | F2 구현, AI 설정(켜기/끄기, Gemini·NIM, API 키) | **구현 완료** | 단위 테스트, 가짜 AI 서버로 Chromium E2E 통과 |
| M3-평가 | 실제 쇼핑몰과 실제 API 키로 확인, Gemini·NIM 한국어 정확도 비교 | 다음 | 상품 10~20개 추출 정확도, 스크린리더 3종 확인 |
| M0 조사 | 대상 쇼핑몰 선정, 접근성 문제 기준선 측정 | 예정 | 사이트별 라벨 없는 요소 수 집계 |
| M1 라벨링 | DOM 단서만으로 F1 | 예정 | NVDA에서 주입 라벨이 읽힘 |
| M2 라벨링 AI | F1에 같은 AI 설정 재사용 | 예정 | 라벨 정확도 측정 |
| M4 구조 요약 | F3 | 예정 | 단축키로 요약 열고 이동 가능 |
| M5 평가 | 전체 지표, 사용자 테스트 | 예정 | 9장 지표 전부 측정 |

## 11. 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| 스크린리더가 동적으로 주입한 라벨을 늦게 반영하거나 반영하지 않음 | F1 무력화 | M1에서 스크린리더별로 먼저 확인, 필요하면 페이지 로드 직후 일괄 주입 |
| 센스리더 동작 정보 부족 | 국내 주 사용자 검증 불가 | 실제 사용자 테스트에 센스리더 사용자 포함 |
| 한국어 OCR 정확도 부족 | F2 품질 저하 | M3-평가에서 Gemini·NIM 모델 비교 후 기본 모델 선정 |
